# PDA marker research

## Scope and source

This inventory was produced from the local `D:\Hope\Anomaly` installation. Its `changes152to153.txt` identifies the installation as Anomaly 1.5.3. Only base-game archives were extracted; extracted game content is kept in the user's temporary directory and is not committed or copied into this repository.

The repeatable extraction entry point is `tools/extract_anomaly_resources.ps1`. It reads `configs.db0`, `scripts.db0`, and `textures_ui.db0` using the converter supplied with the game. The extraction used here contained 3,802 config files, 414 scripts, and 529 UI texture resources (including DDS and THM files).

## Findings

- Map marker definitions are in `configs/ui/map_spots.xml` and the 16:9 variant `map_spots_16.xml`, with included definitions from `map_spots_mp.xml`, `map_spots_relations.xml`, and `map_spots_complex.xml`.
- Icon IDs and atlas coordinates resolve through `configs/ui/textures_descr/*.xml`. Resolved source images include `textures/ui/ui_actor_hint_wnd.dds`, `ui_common.dds`, and `ui_hud.dds`; exact source path and crop are recorded per texture layer.
- The extracted inventory contains **472 definition records across the five files, representing 254 distinct technical IDs and 514 image layers**. The 16:9 and standard files intentionally repeat many IDs with separate sizing/layout definitions. Animation and state attributes are present on 105 records.
- One map marker references `ui_alife_combat`, which is not defined in the extracted texture description XML and has no matching UI DDS in `textures_ui.db0`. It remains explicitly unresolved; no guessed DDS path or replacement is recorded.
- Existing Anomaly add-ons identify `map_spots.xml`/`map_spots_16.xml` as sizing/configuration touchpoints and use dedicated DDS atlases. They also show that `location_level` and load order can affect marker visibility. See [Visible PDA MAP Icons - Bigger and Brighter V4](https://www.moddb.com/mods/stalker-anomaly/addons/visible-pda-map-icons-bigger-and-brighter) and the Anomaly 1.5.3-tested [Vanilla Player Map Marker Revival](https://www.moddb.com/mods/stalker-anomaly/addons/vanilla-map-marker-newpda-manarrow-revival).
- DXML edits XML at load time through `modxml_<name>.script` and requires Anomaly Modded Exes. Inspection of the installed DXML core confirms `query`, `iterateChildren`, `setText`, `setElementAttr`, and `removeElementAttr`; an existing Anomaly script uses `on_xml_read` to patch both map_spots layouts. This is enough API evidence for a targeted XML patch, but it does not prove custom DDS lookup or render behavior. See [upstream DXML documentation](https://github.com/themrdemonized/STALKER-Anomaly-modded-exes/blob/main/docs/DXML.md).

## Inventory status

`assets/manifest/icons.json` is generated by `tools/inventory_icons.py` from the five map spot files and all extracted texture descriptions. Each record carries its technical ID, source config, display dimensions/attributes, references, texture layer IDs, source file and atlas region where resolvable, animation hints, implementation status, and in-game verification status.

The definition inventory is complete for the five base-game files listed above. One source symbol, `ui_alife_combat`, has no descriptor or archived UI DDS; it is attached to the `alife_combat_spot` definition in both layouts. Its combat-contact purpose is evident from the configured ID and binding, but the original image is unresolved. The manifest records this explicitly and the validator checks all five referenced source DDS atlases and their available rectangle bounds.

The initial semantic-glyph implementation was rejected because it replaced every nested layer of a marker with one generic image. That erased faction identity, specialized task shapes, borders, and some visual states. The following conservative 2× restoration was also rejected after visual review: although technically accurate, it retained the oversized cyan transition markers and cluttered global-map hierarchy.

The current implementation uses an original 1024×1024 DXT5 atlas built from deterministic Pillow drawing primitives. It maps 247 visible technical IDs to 50 semantic categories. Warm ivory handles navigation, amber indicates objectives and loot, rust red indicates danger, muted sage indicates allies and services, and steel gray handles strategic information. Restrained faction and anomaly variants keep those identities distinguishable without returning to neon colors. Transition markers are reduced from 19×21 to 5×5 and use one directional chevron inside a compact badge. Low-priority tactical marks use 3–5 pixel display sizes, while primary objectives use 7×7.

DXML selects the category by marker definition name, updates its display dimensions, disables zoom-driven icon growth, and redirects each texture layer to the new atlas. It keeps binding nodes, heading angles, location levels, visibility thresholds, animation timing and XML order. Nested objective borders are resized to the primary icon plus one pixel on each side. Secondary objective layers use a restrained pulse ring; redundant decorative layers become transparent. Because the atlas artwork is original, the tagged release can contain a ready-to-install MO2 archive.
